## 🎯 Goal

Java speaks **objects** 🧱. Databases speak **tables** 📊. How do they understand each other? 🤔

At the end of this chapter you will know:

- How Java talks to a database the **hard way**: **JDBC** (with a real, working program!)
- Why that's so much **boring** work 😩
- What an **ORM** is: an automatic translator between objects and tables 🗣️
- What **JPA**, **Hibernate** and **Spring Data JPA** are — and how they fit together
- What your code will look like in the next chapters (spoiler: **very** short 🤯)

> 🌱 This is mostly a "thinking" chapter, with **one** program to run. Chapters 71–73 put everything into practice.

## 📝 New words

| Word | Simple meaning |
|---|---|
| **JDBC** | **J**ava **D**ata**b**ase **C**onnectivity: Java's **basic** way to send SQL to a database. |
| **Driver** | A library that knows how to talk to **one** kind of database (H2, PostgreSQL...). |
| **`ResultSet`** | The rows that come back from a `SELECT`, in JDBC. You read them one by one. |
| **Mapping** | Copying data between a **row** and an **object** (column → field). |
| **ORM** | **O**bject-**R**elational **M**apping: a library that does the mapping **for** you. 🗣️ |
| **JPA** | **J**akarta **P**ersistence **A**PI: the Java **standard** (the rules) for ORMs. 📜 |
| **Hibernate** | The most popular **ORM** that follows the JPA rules. It does the real work. 💪 |
| **Spring Data JPA** | A Spring helper on top of JPA that writes even the **repository** code for you. ✨ |
| **Persist** | To **save** an object into the database. |

## 📖 Story: Two people, two languages 🗣️

Imagine a Japanese chef 🇯🇵 and an Italian waiter 🇮🇹 working together. The chef speaks only Japanese, the waiter only Italian. 😵

**Way 1:** The waiter learns to **write every order in Japanese**, word by word, with a dictionary. 📖 Slow, tiring, and full of mistakes.

**Way 2:** The restaurant hires a **translator** 🧑‍💼. The waiter just speaks Italian; the translator handles everything. 😌

In our app:

| Restaurant | Our app |
|---|---|
| The Italian waiter 🇮🇹 | Your **Java** code (objects: `Student`) |
| The Japanese chef 🇯🇵 | The **database** (tables, rows, SQL) |
| Writing Japanese with a dictionary 📖 | **JDBC** — you write SQL and copy every column by hand |
| The translator 🧑‍💼 | **JPA / Hibernate** — the **ORM** |

## 🔌 Part 1: The hard way — JDBC

Every Java program that talks to a database uses **JDBC** underneath. Let's write one **by hand**, once, so you see what happens inside. 🔍

Save this as **`JdbcDemo.java`** in the folder where you put the H2 jar (Chapter 68):

```java
import java.sql.Connection;
import java.sql.DriverManager;
import java.sql.PreparedStatement;
import java.sql.ResultSet;
import java.sql.SQLException;
import java.sql.Statement;
import java.util.ArrayList;
import java.util.List;

public class JdbcDemo {

    record Student(Long id, String name, String email, int age) {
    }

    public static void main(String[] args) throws SQLException {
        try (Connection connection = DriverManager.getConnection("jdbc:h2:mem:demo", "sa", "")) {

            // 1. Create the table
            try (Statement statement = connection.createStatement()) {
                statement.execute("""
                        CREATE TABLE students (
                            id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
                            name VARCHAR(50) NOT NULL,
                            email VARCHAR(100) NOT NULL UNIQUE,
                            age INT)""");
            }

            // 2. Save a student
            String insertSql = "INSERT INTO students (name, email, age) VALUES (?, ?, ?)";
            try (PreparedStatement insert = connection.prepareStatement(insertSql)) {
                insert.setString(1, "Sara Ahmed");
                insert.setString(2, "sara@school.com");
                insert.setInt(3, 12);
                insert.executeUpdate();

                insert.setString(1, "Tom Brown");
                insert.setString(2, "tom@school.com");
                insert.setInt(3, 13);
                insert.executeUpdate();
            }

            // 3. Read all students and turn each row into a Java object
            List<Student> students = new ArrayList<>();
            try (Statement statement = connection.createStatement();
                 ResultSet rows = statement.executeQuery("SELECT id, name, email, age FROM students")) {
                while (rows.next()) {
                    Student student = new Student(
                            rows.getLong("id"),
                            rows.getString("name"),
                            rows.getString("email"),
                            rows.getInt("age"));
                    students.add(student);
                }
            }

            for (Student student : students) {
                System.out.println(student);
            }
        }
    }
}
```

Run it with the H2 jar on the classpath:

```
java -cp h2-2.4.240.jar JdbcDemo.java
```

**Output:**

```
Student[id=1, name=Sara Ahmed, email=sara@school.com, age=12]
Student[id=2, name=Tom Brown, email=tom@school.com, age=13]
```

🎉 It works! Java created a table, saved two students, and read them back.

### 🔍 Line by line

| Code | Meaning |
|---|---|
| `import java.sql...` | JDBC is part of **Java itself** (the `java.sql` package). |
| `DriverManager.getConnection("jdbc:h2:mem:demo", "sa", "")` | ⭐ Open a **connection** to the database: URL, user, password. (The H2 **driver** in the jar knows how to do it.) 🔌 |
| `try (Connection connection = ...)` | **Try-with-resources** (Chapter 33): the connection is **closed** automatically at the end. Very important — open connections waste the database's resources! |
| `connection.createStatement()` | A "statement" object that can send SQL. |
| `statement.execute("""...""")` | Send a `CREATE TABLE` (a text block — Chapter 9). |
| `"INSERT INTO students (name, email, age) VALUES (?, ?, ?)"` | SQL with **`?`** placeholders. |
| `connection.prepareStatement(insertSql)` | A **prepared statement**: SQL with holes to fill. |
| `insert.setString(1, "Sara Ahmed");` | Fill hole number **1** (counting starts at 1 here, not 0! 😅). |
| `insert.setInt(3, 12);` | Fill hole 3 with a number. |
| `insert.executeUpdate();` | Run it! (One row added.) |
| `statement.executeQuery("SELECT ...")` | Run a `SELECT` → a **`ResultSet`** (the rows). |
| `while (rows.next())` | Go to the next row, as long as there is one (a `while` loop — Chapter 13). |
| `rows.getLong("id")`, `rows.getString("name")`... | ⭐ Read **each column** of the current row, **by hand**... |
| `new Student(...)` | ...and build a Java object from them. That's **mapping**. |

### 🛡️ Why the `?` placeholders?

Never glue user input directly into SQL text:

```java
"SELECT * FROM students WHERE name = '" + name + "'"   // ❌ DANGEROUS!
```

A bad person could type a "name" like `x' OR '1'='1` and change your SQL! 😈 This attack is called **SQL injection** — one of the most famous security problems on the internet. With `?` placeholders, the database treats the value **only as data**, never as SQL. ✅ (Good news: JPA always uses placeholders for you.)

## 😩 Part 2: Why JDBC is painful

Look at that program again. To save and read **one** simple class, we needed:

- ✍️ SQL written **by hand** (with column names as **text** — a typo is only found when it runs!)
- 🔢 `setString(1, ...)`, `setString(2, ...)`, `setInt(3, ...)` for **every** field, in the right order
- 🔁 `rows.getLong("id")`, `rows.getString("name")`... for **every** column, for **every** class
- 🚪 Opening and closing connections, statements and result sets
- 🐛 `SQLException` everywhere

Now imagine a real app: **50** classes, each with **20** fields, and **find by id**, **find by email**, **update**, **delete**... for **all** of them. That's **thousands** of lines of boring, copy-paste code. 😵‍💫

**There must be a better way!** 🤔

## 🗣️ Part 3: The translator — ORM

An **ORM** (Object-Relational Mapping) is a library that translates **automatically** between **objects** and **tables**:

```
      Java world 🧱                    ORM 🗣️                   Database world 📊
 ┌──────────────────────┐                                ┌──────────────────────────┐
 │ class Student        │                                │ table students           │
 │   Long id            │  ◄───── field = column ─────►  │   id     BIGINT          │
 │   String name        │                                │   name   VARCHAR(50)     │
 │   String email       │                                │   email  VARCHAR(100)    │
 │   int age            │                                │   age    INT             │
 └──────────────────────┘                                └──────────────────────────┘
   one object (Sara)     ◄─────── object = row ───────►    one row (1, Sara Ahmed, ...)

   repository.save(sara)    ──► ORM writes:  INSERT INTO students (...) VALUES (?, ?, ?)
   repository.findById(1)   ──► ORM writes:  SELECT ... FROM students WHERE id = ?
                                ORM reads the row and builds a Student object for you! ✨
```

| You do | The ORM does |
|---|---|
| Put **labels** on your class (`@Entity`, `@Id`) | Creates the **table** for you (if you want) |
| Call `save(student)` | Writes the `INSERT` or `UPDATE` |
| Call `findById(1)` | Writes the `SELECT`, reads the columns, builds the object |
| Change a field and save | Writes the `UPDATE` |

No more `setString(1, ...)`. No more `rows.getLong(...)`. 🎉

## 🧩 Part 4: JPA, Hibernate, Spring Data JPA — who's who?

These three names confuse **everybody** at first. 😅 Here's a simple picture:

```
 ┌──────────────────────────────────────────────────────────────┐
 │  Spring Data JPA  ✨  "I write the REPOSITORY for you."         │  ← Chapter 72
 ├──────────────────────────────────────────────────────────────┤
 │  JPA  📜  The RULES (a standard): @Entity, @Id, @Column...     │  ← Chapter 71
 ├──────────────────────────────────────────────────────────────┤
 │  Hibernate  💪  Follows the rules and does the real work        │
 │                (writes the SQL, builds the objects)            │
 ├──────────────────────────────────────────────────────────────┤
 │  JDBC  🔌  Sends the SQL to the database (what you did above)  │
 ├──────────────────────────────────────────────────────────────┤
 │  Driver (H2, PostgreSQL...)  →  🗄️ the database                │
 └──────────────────────────────────────────────────────────────┘
```

| Name | What it is | Like... |
|---|---|---|
| **JPA** (Jakarta Persistence) 📜 | A **standard**: a list of rules and labels (`@Entity`, `@Id`...). Not a program! | The **rules** of football ⚽ |
| **Hibernate** 💪 | A **library** that **follows** the JPA rules and does the work. | A **team** that plays by those rules |
| **Spring Data JPA** ✨ | A Spring helper on **top**: you write an **interface**, it writes the repository code. | A **coach** who makes the team even easier to use |
| **JDBC** 🔌 | The basic Java way to send SQL. Hibernate uses it **underneath**. | The **ball** everyone kicks |

All of them came with **one** dependency in Chapter 69: `spring-boot-starter-data-jpa`! 📦 (Remember the log line `Hibernate ORM core version 7.4.5.Final`? That's Hibernate starting.)

> 💡 **Why a standard?** Because there are other JPA libraries too (like EclipseLink). If you write code with JPA's rules, you could switch libraries without changing your code. In practice, almost everybody uses Hibernate. 💪

## 🔮 Part 5: A sneak peek

Here's how the **same** job as our 60-line JDBC program will look in Chapters 71–72. Don't type it yet — just look! 👀

**The entity** (Chapter 71) — a class with labels:

```java
@Entity
@Table(name = "students")
public class Student {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    private String name;
    private String email;
    private int age;

    // constructors, getters, setters...
}
```

**The repository** (Chapter 72) — **one** line! 🤯

```java
public interface StudentRepository extends JpaRepository<Student, Long> {
}
```

**Using it:**

```java
studentRepository.save(new Student("Sara Ahmed", "sara@school.com", 12));   // INSERT
List<Student> all = studentRepository.findAll();                            // SELECT
```

No SQL. No `setString`. No `getLong`. No closing connections. And **no class** that implements `StudentRepository` — Spring Data **creates it for you** at startup. 🪄

And the best part: you can **still see** the SQL that Hibernate writes for you, in the log:

```
Hibernate: 
    insert 
    into
        students
        (age, created_at, email, name, teacher_note, id) 
    values
        (?, ?, ?, ?, ?, default)
```

(A real line from Chapter 72! Look: Hibernate uses `?` placeholders too — no SQL injection. 🛡️)

## ⚖️ Part 6: JDBC or JPA?

| | JDBC 🔌 | JPA / Spring Data JPA ✨ |
|---|---|---|
| Code to write | 😩 A lot | 😊 Very little |
| You write SQL | Always | Rarely (only for special queries — Chapter 74) |
| Mapping rows ↔ objects | By hand | Automatic |
| Control over every detail | Full | Less (but enough for most apps) |
| Used in Spring Boot apps | Sometimes, for special cases | ✅ **Most of the time** |

In this book, we use **Spring Data JPA**. But now you know what happens **underneath**: JPA → Hibernate → **JDBC** → the database. Nothing is magic! 🧠✨

## 💻 Mini project: Books with JDBC 📚

Write **`BookJdbc.java`** (plain Java, like `JdbcDemo`):

1. Create a `books` table (`id` automatic, `title`, `author`, `published`).
2. Save Matilda (Roald Dahl, 1988), The Hobbit (J.R.R. Tolkien, 1937) and Charlotte's Web (E.B. White, 1952). Tip: write a small method `saveBook(...)` so you don't repeat the `set...` lines!
3. Find the books published **before 1960**, oldest first — with a **`?`** placeholder for the year.
4. Print each one as a `Book` record.

<details>
<summary>Click to see the answer</summary>

```java
import java.sql.Connection;
import java.sql.DriverManager;
import java.sql.PreparedStatement;
import java.sql.ResultSet;
import java.sql.SQLException;
import java.sql.Statement;

public class BookJdbc {

    record Book(Long id, String title, String author, int published) {
    }

    public static void main(String[] args) throws SQLException {
        try (Connection connection = DriverManager.getConnection("jdbc:h2:mem:library", "sa", "")) {

            try (Statement statement = connection.createStatement()) {
                statement.execute("""
                        CREATE TABLE books (
                            id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
                            title VARCHAR(100) NOT NULL,
                            author VARCHAR(50) NOT NULL,
                            published INT)""");
            }

            String insertSql = "INSERT INTO books (title, author, published) VALUES (?, ?, ?)";
            try (PreparedStatement insert = connection.prepareStatement(insertSql)) {
                saveBook(insert, "Matilda", "Roald Dahl", 1988);
                saveBook(insert, "The Hobbit", "J.R.R. Tolkien", 1937);
                saveBook(insert, "Charlotte's Web", "E.B. White", 1952);
            }

            String selectSql = "SELECT id, title, author, published FROM books WHERE published < ? ORDER BY published";
            try (PreparedStatement select = connection.prepareStatement(selectSql)) {
                select.setInt(1, 1960);
                try (ResultSet rows = select.executeQuery()) {
                    while (rows.next()) {
                        Book book = new Book(rows.getLong("id"), rows.getString("title"),
                                rows.getString("author"), rows.getInt("published"));
                        System.out.println(book);
                    }
                }
            }
        }
    }

    static void saveBook(PreparedStatement insert, String title, String author, int published) throws SQLException {
        insert.setString(1, title);
        insert.setString(2, author);
        insert.setInt(3, published);
        insert.executeUpdate();
    }
}
```

`java -cp h2-2.4.240.jar BookJdbc.java`

**Output:**

```
Book[id=2, title=The Hobbit, author=J.R.R. Tolkien, published=1937]
Book[id=3, title=Charlotte's Web, author=E.B. White, published=1952]
```

Notice: in Java code, `"Charlotte's Web"` needs **no** double quote — the `?` placeholder takes care of it. Another win for placeholders! 🎉 (And imagine writing this for 50 classes... now you **really** want JPA. 😄)

</details>

## ⚠️ Common mistakes

### Mistake 1: Gluing values into SQL text

`"... WHERE name = '" + name + "'"` → **SQL injection**! 😈 **Fix:** Always use `?` placeholders (`PreparedStatement`) — or JPA, which does it for you.

### Mistake 2: Forgetting to close connections

Without `try (...)`, connections stay open. After a while, the database says "too many connections" and your app stops working. **Fix:** Try-with-resources. (With Spring, the pool and JPA handle this for you. 🏊)

### Mistake 3: Counting placeholders from 0

`setString(0, ...)` → an error. In JDBC, placeholders start at **1**. 😅

### Mistake 4: Thinking "JPA = Hibernate"

They're related, but not the same: JPA is the **rulebook** 📜, Hibernate is the **player** 💪. (People mix them up all the time — now you won't!)

## ✅ Summary

- Java talks to databases with **JDBC** 🔌: connections, `PreparedStatement` with **`?`** placeholders, and `ResultSet` rows.
- With JDBC, you write SQL and copy every field **by hand** — lots of boring, error-prone code. 😩
- **Always** use `?` placeholders — never glue user input into SQL (**SQL injection** 😈).
- An **ORM** 🗣️ translates automatically: **class ↔ table**, **field ↔ column**, **object ↔ row**.
- **JPA** 📜 = the standard (rules and labels). **Hibernate** 💪 = the library that does the work. **Spring Data JPA** ✨ = writes your repositories for you.
- All of it came with `spring-boot-starter-data-jpa`. Underneath, it's still JDBC.
- Next: **entities** (Chapter 71) and **repositories** (Chapter 72) — your 60 lines of JDBC become about 10. 🤯
